# 状態モデルと動きの文法

計器・管制風の画面が「単なる装飾」にならないよう、状態とアニメーションの意味を揃える。

## 状態モデル（5 状態の分離）

解説する地理・インフラ・観測データの状態は、最低限次の区別を意識する。

1. **正常 / 基準内**: 通常の背景・落ち着いた線。目立たせすぎない。
2. **注意 / 接近**: しきい値に近づいた状態。補助色（例: 琥珀・橙）と状態語の更新で予兆を示す。
3. **警戒 / 異常 / 超過**: 面積のある塗り面・反転ラベル・太い境界線で画面の主役として切り替える。
4. **確定 / 解除 / 復旧**: 「確認した」ことと「異常が解消した」ことを混同しない。復旧時は通常色へ戻すだけでなく変化の履歴が追えるようにする。
5. **欠測 / 不明 (`NO DATA`)**: 観測不能・未集計・範囲外を「0」や「正常」と同じ色にしない。グレーや斜線、明示ラベルで分離する。

## 動きの文法（モーション設計）

- **静止を基準にする**: 全要素が常に明滅・回転・浮遊していると、本当に重要な変化が埋もれる。変化が起きる瞬間まで通常状態は静止させる。
- **段階の連なりを作る**: FUI 的な図解では「接続・観測開始 → 計測・数値更新 → しきい値判定・範囲確定」の順に時間差をつけて出すと、因果関係が直感的に伝わる。
- **位置ズレを避ける**: 数値がカウントアップ・変化するときは等幅数字（`tabular-nums`）を使い、桁の変化で文字全体が左右にガタつかないようにする。
- **説明できる動きだけ残す**: 境界線の描画（`draw`）、数値の増加（`counter`）、範囲の出現（`fade` / `rise`）など、「何の物理・統計変化を表す動きか」を言語化できるアニメーションだけを採用する。

## HTML / SVG 図版の実装テクニック

`panel` 用の図版や専用 HTML コンソール画面を組む際は、次の実装パターンが有効である。

- **ルート属性による一括状態切替（`data-mode`）**: 個別要素の色をばらばらに書き換えるのではなく、ルート要素の属性（例: `data-mode="normal" | "alert" | "emergency"`）1 つを切り替え、CSS 変数で正常色から警戒色へ画面全体を一斉反転させる。
- **1 色 1 役割のトークン分離**: グラデーションで色を混ぜず、「見出し・系統ラベル（橙）」「正常値（緑）」「空間・地形ワイヤーフレーム（シアン）」「異常・超過のみ（赤）」のように色ごとの役割を固定する。
- **機械的長体（`scaleX`）**: 短い見出しや判定語に強い緊張感を持たせたい場合、`transform: scaleX(0.82); transform-origin: left center;` のような横幅圧縮を単発の主見出しに限定して使う（本文や注釈には使わない）。
- **動画圧縮を壊さない質感の扱い**: 走査線（`repeating-linear-gradient`）やビネットを入れる場合は不透明度をごく低く（4〜6% 以下）抑え、H.264 圧縮でモアレや文字潰れを起こす常時フリッカー点滅や極小フォント・過剰なグローは避ける。
