# モーション設計の原則・イージング・表現技術

地図や図解の動きが「機械的」「単調」「何が主役か分からない」状態を防ぐためのモーション設計指針と、外部ツール・ライブラリの位置づけをまとめる。テンプレート標準のショット JSON 機能で実現できる範囲と、外部で事前生成・カスタム図版化する範囲を区別して使う。

## 1. 動きを設計する前の原則（Intent First）

アニメーションは「動かせるから動かす」のではなく、次の 4 つの目的のいずれかに紐づけて設計する（`motion-design-skill` の設計思想に基づく）。

1. **視線誘導**: 次に見てほしい場所・数値・見出しへ注意を向ける。
2. **階層の提示**: 背景・主図・注釈の前後関係や因果の順序を示す。
3. **意味・変化の伝達**: 時間の経過、増加、境界の拡大など、物理・統計上の変化を表す。
4. **余韻と緩急**: 切り替わりの区切りをつけ、静止との対比で緊張と緩和を作る。

目的を言語化できない常時アニメーション（無意味な明滅・浮遊・回転）は避け、**静止を基準**として局面の切り替わりで動かす。

## 2. ディズニー 12 原則の地理解説動画への翻案

手描き・UI アニメーションの古典原則のうち、地理・図解解説動画で特に効く原則は次の通り。

| 原則 | 地理解説動画での使い方 |
|---|---|
| **Staging（演出・視線誘導）** | 1 画面で同時に動かす主役は 1 つに絞る。地図カメラが激しく動いている最中に、複雑な図版や大量の文字を同時に動かさない。 |
| **Slow In & Slow Out（緩急）** | 空間移動（カメラ移動・パネルの出入り・線の引き始めと引き終わり）に等速（`linear`）を使わない。加速・減速をつけて重さと落ち着きを出す。 |
| **Anticipation（予備動作）** | 遠方へ大きく移動する直前に少し引く（`flyPanAndZoom` の放物線軌道）、あるいは注視枠を出してから中身を展開する。 |
| **Follow Through & Overlapping Action（時間差 / Stagger）** | 見出し・数値・凡例・ラベルを 0 フレーム目に一斉に出さず、**0.1〜0.2 秒（30fps で 3〜6 フレーム）**ずつずらして因果の順に出す。ただし全要素の出揃いに 1 秒以上かけない。 |
| **Secondary Action（副次動作）** | 立ち絵のまばたき・口パク、地図上の波紋や点滅マーカーなど、主役の理解を邪魔しない範囲で画面に生気を持たせる。 |

## 3. イージングと決定論的タイムラインの原則

### レンダラーのイージング関数との対応

`packages/renderer/src/lib.ts` の `ease(kind, t)` および `easeOutBack(x)` は以下の使い分けを基準とする。

- **`out`（減速 / `1 - (1 - t)^3`）**: 出現（Entrance）、パネルや文字の着地、カメラの到着、数値のカウントアップ。素早く現れて自然に止まるため最も多用する。
- **`inOut`（加減速）**: 地図カメラの移動（`shot.ease` の既定値）、線描画（`draw`）など、始点と終点の両方が画面内に見えている連続移動。
- **`in`（加速 / `t^3`）**: 退場（Exit）。画面から去る動きは後半を速くして余白を早く空ける。
- **`easeOutBack`**: タイトルカード（`chapter`）やピン・スタンプの登場など、わずかなオーバーシュートで弾み・注目感を出したい場面に限定して使う。
- **`linear`**: 連続回転、進行バー、一定速度のスクロールなど「止まらない定常運動」のみに使う。

### 決定論的フレーム補間（コマ撮り互換性）

`packages/renderer/` は Playwright で 1 フレームずつ時刻 `t` を進めてキャプチャする決定論的レンダラーである（Remotion 等のフレーム駆動動画エンジンと同じ設計思想）。

カスタム HTML/SVG の図版（`panel` 用の別ページや将来のオーバーレイ拡張）を作る場合、次の規約を守る。

- **禁止事項**: CSS `transition` / `@keyframes`、`setInterval` / `setTimeout`、`requestAnimationFrame`、`Math.random()` に状態変化を委ねない（書き出しマシンの速度やフレームレートでズレや非再現性が起きる）。
- **必須手法**: すべての視覚状態（位置・透明度・スケール・線長）を、フレーム時刻 `t`（またはフレーム番号）を入力とする純粋関数で計算し、区間外は必ず `[0, 1]` にクランプ（`clamp01`）する。
- **バネ物理（Spring）**: 有機的な弾みが必要な場合も、リアルタイム物理演算ループではなく、経過時間 `t` に対して解析解または固定ステップで評価できる減衰振動（`spring(t, { stiffness, damping, mass })`）として実装する。

### 静止画のゆっくりした寄り（ケン・バーンズ）を ffmpeg の外で作るとき

- ffmpeg の `zoompan` は切り出す位置を整数の画素に丸めるため、5 秒で 8% のようなゆっくりした寄りはガタつく。キャンバスを 2 倍、4 倍に広げても半分になるだけだった。
- フレームは Pillow などで小数の位置に描き、ffmpeg には生のフレームを渡す。写真は先に Lanczos で画面の大きさまで縮め、アフィン変換では拡大だけにする。Pillow の変換は縮小のときに折り返し（ちらつき）を防がないため。
- 測り方: 時間方向の 2 階差分（|f[i+1] − 2f[i] + f[i−1]| の画素平均）。滑らかな動きでは 1 階差分より小さく、ガタつくと大きくなる。2026-11-23 のリミナルの写真の歩行では、完成動画で zoompan 2 倍が 2.80、小数の位置に描くと 0.81 だった（実装: `packages/pipeline/photo_push.py`。`photo_push.py <写真> <出力.mp4> --focus=0.5 --zoom=0.08` で 1 カット書き出せる。滑らかさは `temporal_roughness` で測れる）。

## 4. 図解・外部アニメ・3D 表現の使い分けと参考スタック

テンプレート標準のショット JSON で表現できない高度な図解や演出が必要な場合、**外部で事前生成した動画／連番素材・静止画図版を `panel` 等として取り込む**か、レンダラー拡張時の設計リファレンスとして以下の技術を使い分ける。

| 表現したいもの | アプローチと参考ライブラリ・手法 | 本リポジトリでの位置づけ |
|---|---|---|
| **仕組み・インフラの立体図解・分解図** | アイソメトリック SVG 線画（`hairline` 系）や分解図解（`anatomy` / `anatomy-reveal` 系）。内部構造を斜め投影や展開配置で 1 枚に収める | 静止画または時刻駆動 SVG を `panel` として配置し、ナレーションに合わせて注釈を重ねる |
| **幾何・数式・アルゴリズムの図解動画** | **Manim**（Python 製の数式・幾何・ネットワーク図解アニメエンジン） | 地図だけでは説明しにくい空間統計や力学・物理モデルの解説パートを別動画／連番として生成し差し込む |
| **複雑な 2D ベクターアイコン・図解アニメ** | **Lottie (`lottie-web`)** | ベクターアニメ JSON を `goToAndStop(frame, true)` でフレーム同期再生する拡張候補 |
| **HTML/DOM の精密タイムライン制御** | **GSAP**（タイムラインの `.seek(t)` 制御） / **Motion**（スプリング設計の語彙） | カスタム図版で複数要素の Stagger や複合タイムラインを時間軸に同期させたい場合の設計参考 |
| **3D 空間・ポストプロセス・粒子・調整 UI** | **Three.js**（`packages/renderer` 内の PLATEAU 建物描画で既に採用）、ポストプロセス（Bloom / DoF）、パーティクル（`three.quarks`）、調整 UI（`Tweakpane`） | 都市・地形の WebGL 表現を拡張する際の候補。ただし過剰なブルームや常時パーティクルは H.264 圧縮と字幕可読性を損なうため抑制的に使う |
