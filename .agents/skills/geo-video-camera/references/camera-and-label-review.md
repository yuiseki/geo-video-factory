# カメラ移動とラベルの点検

## 動きの設計

- 字幕帯を地図の構図に含める。`cameraPadding` で下部などを確保し、地物や経路の主要部分が字幕・立ち絵に隠れない画角を選ぶ。余白は 1920×1080 を基準に指定し、各出力サイズに比例する。
- 地点名をずらすときは `label` の `at` に実地点を置き、`offset` と `leader: true` で線をつなぐ。線の端とマーカーはカメラ移動後に毎フレーム投影される。概略座標には概略と添える。距離円は地理座標上で作り、縮尺が小さければ詳細カットで見せる。

- カメラは場所や話題の関係を伝えるために動かす。毎ショット同じ向き・距離で回るだけにせず、静止、川に沿う移動、広域、寄り、写真や図解の切り替えを使い分ける。参考動画を指定されたら、その実映像を時系列で見て、何をどこからどこへどの時間で見せたかを確認する。
- 遠い地点をつなぐ場合、出発地で引く → 両方の地域が分かる広域 → 到着地に寄る、という動きが使える。時間を十分に取って、地名を添える。架空の線を実際の移動経路のように表示しない。静止画だけでなく、再生速度で動画を見て、急加速やズーム酔い、タイル読み込みを確認する。
- 大陸をまたぐ長距離遷移では、任意の中継地点を多数並べて経路のように見せない。まず出発地の近景を見せ、同じ中心のまま少し引いて周辺を2秒程度静止する。次に目的地へ中心を移しながらさらに引き、出発地と目的地を同時に含む広域構図で2秒程度静止する。そこから目的地へ移動しながら周辺構図まで寄り、2秒程度静止した後、目的物へ最後のプッシュインを行う。移動、位置関係の読解、最終的な注目を別ショットに分け、隣接ショットの終了カメラと開始カメラを同じ値にする。
- 長距離遷移の広域構図は、出発地と目的地の経緯度から Web Mercator 上の bbox を求め、実際の viewport とラベル用 padding を使って `center` と `zoom` を計算する。MapLibre の world size は `512 × 2^zoom` であり、256 px タイルを前提に概算しない。算術平均の緯度や目測の zoom を採用せず、両端を画面座標へ再投影して padding 内に収まる自動テストを置く。そのうえで試写し、文字枠も画面内にあることを確認する。中間地点という地名のない場所を目的地のように見せず、両端のラベルを表示して構図の意味を伝える。真俯瞰を指定された場合は全ショットの `pitch: 0` を保ち、広域部だけ斜めにしない。
- 一つの長距離移動を短い台詞の長さに押し込まない。`duration` は音声より短くならないが、長く指定すると発話後にも映像と字幕が続く。長すぎる無音も確認し、必要なら会話やショット配分を調整する。
- 既定の `inOut` は3次のイージングでピーク速度が大きい。`smooth` は `3t²−2t³` でピークを抑える。ただし通常の `center` / `zoom` 独立線形補間 (`path: "linear"`) のまま長距離移動と大きなズーム変化を同時に行うと、画面上の見かけのパン速度が $2^{\Delta z}$ 倍に変化して破綻する（ズームアウト時は起点が即座に画面外へ飛び、ズームイン時は無関係な海域や遠方へ潜ってから終盤で猛スピード横滑りする）。長距離遷移やズーム差の大きいパン＋ズームでは、ショットに `"path": "fly"`（van Wijk & Nuij 型のズーム・パン結合補間、必要なら `"curve"` で弧の高さを調整、既定 `1.42`）を指定し、広域で水平移動してから目的地へ垂直降下する軌道にする。
- 日本国外の近景（`z ≈ 6〜7` 等）を含む長距離ショットでは、`worldFade` の上限が低すぎると NASA Blue Marble が消えて地理院タイルの日本国外の暗部・海面欠損が露出するため、`worldFade` を日本の近景側（例: `[8, 9.5]`）に寄せて背景のクロスフェード破綻を防ぐ。
- 複数の `keys` は区間ごとに補間されるので、キー間の距離・ズーム差・時間幅が不均等だと速度が急変する。`ease` を変えるだけで安全な速度になるとは限らない。`from` / `to` / `keys` は直前・直後の画との連続性も確認する。
- `shot_effects.geographic_transition` は広域へ引いてから目的地へ寄るキーの生成を共通化する。`duration` と `ease` はショット側で決める。生成されたキーは素材や目的地の位置に合わせて調整し、連続動画で判断する。

## 実際に見て確認する項目

- 冒頭・中間・末尾だけでなく、最大加速、ズームの切り替え、ラベルが接近する時刻も確認する。ラベルが止まった状態で読めても、移動中や引きの縮尺で重なることがある。
- 3D建物や点群のあるシーンで引く場合、終点と途中の全フレームがデータの実カバレッジ内にあるか確認する。建物が途切れる場所、簡易補完だけになる場所、低解像度タイルへ変わる場所までカメラを引かない。広域の位置関係が必要なら、詳細3Dのショットとは編集点で分ける。
- 3D Tiles を実行時の LOD 選択に任せると、カメラの移動中に建物が後から現れたり消えたりする。先読みやタイルの読み込み完了の待機だけでは防げなかった。動画では、撮る範囲に重なる最も詳しいタイルを事前に取得してすべて固定で載せ、画面の中で LOD を切り替えない。
- 簡易建物や推定材質を連続表示する場合、材質単位の一括色ではなく地物ID単位で色・明度・窓や屋根のパターンを変える。同じ色と模様の建物が連続していないか、近接構図と引いた構図の両方で確認する。乱数表現は地物IDや座標から固定生成し、フレーム間でちらつかせない。
- 隣接するランドマーク名と主題名は、それぞれ正しい地物や適切な地域を指す。駅名は駅、広域名は広域として扱う。異なる二つの名称を同じ座標に置かない。面として広がる地域名を一点に置く場合は、その位置が概略であることが読み取れるようにする。
- 実表示の文字枠同士の重なりや、字幕・立ち絵・写真・画面端との衝突を確認する。名前だけではなく文字枠の外形を比較する。ラベルが接する場合も距離を広げる、表示時刻を分ける、縮尺を変えるなどして読みやすさを確保する。解決するために別の場所を誤って指さない。
- 写真の枠から出る線は撮影地点に固定し、被写体名は対象に付ける。地図を動かしながら複数時刻を確認する。EXIF がない写真に推定位置を付けた場合は、位置を概略と明示する。
- 静止画一覧は構図の候補を絞るためのもの。速度、音声との同期、線の追従は短い動画で確認する。タイル待ちでタイムアウトしたフレームやブラウザーの取得エラーがあればログを調べ、修正して書き出し直す。

## 文字枠の自動検出

テンプレートの `render.mjs` に `--check-label-overlap` を付けると、描画フレームごとに DOM 地名ラベルと他の DOM 地名、字幕、立ち絵、写真枠、パネルの矩形を比較し、初めて重なった時刻を `warning: label overlap` として記録する。`chapter_pipeline.py` に同じオプションを付けると章ごとに検出し、警告のある章で停止する。例 (ホストの資源制限ルールがあれば、それに従って囲む):

```bash
node render.mjs shots/scene.json --out out/label-review --stills 0.5 --no-voice --check-label-overlap
```

静止画はサンプリング間の衝突を見落とす。`osmLabels` の MapLibre 内部文字、写真マーカーの SVG ラベル、出典、画面外への消失は対象外で、矩形の重なりは意図的なものも警告する。本番と同じ大きさ・タイミングの動画で目視する。音声長が異なる `--no-voice` 試写だけで本番の衝突を否定しない。
