# 権利確認・重複監査・EXIF・画像 ID 管理

## 1. 目視確認とイメージ表記

- **必ず中身を目で確かめる**: 検索タイトルやファイル名と実際の被写体が一致しないことがある（例：「京葉工業地域」で検索した写真が単なる港のクレーンだった等）。
- **イメージ写真の注記**: 話題の直接の現場ではないイメージ写真を使う場合は、`caption` や画面注記に `(イメージ)` と明記し、概要欄にも補足する。

---

## 2. 画像の重複監査

- **判定基準**: ファイル名や画像 ID が異なるかではなく、**見る人にとって同じものに見えるか**で判定する。
- **連写・近接撮影の除外**: 同じ場所で同じ被写体を続けて撮った写真（数秒〜数分の差、向きや寄りが少し違うだけのもの）は同じ写真として扱い、1 枚だけ選ぶ。
- **目視のやり方**: 画像ハッシュによる自動判定は、夜間写真の明るさの揺れ等で別画像と誤認しやすい。撮影時刻と撮影地点が近い写真を組にして並べて目で確かめる。
- **再登場の例外**: 意図的に同じ写真を再登場させる場合は、前後の目的・表示方法を変えて意味を持たせる。無関係な写真で話題を代用しない。

---

## 3. 権利の適用範囲と未許諾素材

- **ライセンスを勝手に広げない**: ある写真群に与えられた CC0 や許諾を、他者の写真やプロジェクト内の全素材に広げない。素材 1 点ごとに記録する。
- **共有ページの埋め込み画像**: Web ページや共有ノートに埋め込まれていた歴史写真・資料画像であっても、ページ上で見つかったことだけでは動画への転載許諾を確認したことにならない。博物館・自治体等の一次元ソースの権利表示と二次利用条件を確認する。

---

## 4. 元画像の EXIF と地図への紐づけ

- **元画像の EXIF を使う**: 写真共有サービスなどから撮影日や位置を探すときは、縮小版（EXIF が削られやすい）ではなく元画像の EXIF を確認する。
- **GPS の限界**: EXIF の GPS は撮影地点の概略であり、被写体の位置やカメラの向きを保証しない。地図と実際の橋・建物の位置関係を照合し、特定できないものを事実として断定表示しない。
- **`photo_geo.py` の利用**:
  - `exif_coordinates(path)` で EXIF GPS を `[経度, 緯度]` に変換する（欠損や範囲外はエラー）。
  - `linked_photo(src, caption, position, credit=..., subject=..., bridge=...)` で `photo_marker` を生成する。`at` が撮影地点、`cameraAt` / `cameraLabel` が写っているランドマーク（歴史的なキー名であり `cameraAt` は撮影地点ではない）。不要な「撮影地点（EXIF）」ラベルは付けない。

---

## 5. 共有画像 ID（Gyazo 等）と gitleaks 保護

- **ID を書くこと＝公開**: Gyazo のような共有リンクで開ける写真サービスの画像 ID や URL は、ID が分かれば写真そのものを開けるため、画像ファイルを `.gitignore` していてもリポジトリに ID を書けば写真を公開したことになる。
- **不要な ID を残さない**: 使っていない写真の ID が入った一覧（その日の取得結果メモ等）はリポジトリに置かない。ショット JSON・出典記録・ファイル名に ID が残っていないかも確認する。
- **公開前確認と許可リスト**:
  - リポジトリの `.gitleaks.toml` は、ちょうど 32 桁の小文字 16 進の並びをすべて Gyazo 画像 ID 候補として検出し、pre-commit と GitHub Actions で止める。
  - 新しい写真 ID を残すときは、push する前に `https://gyazo.com/<ID>` の一覧を利用者に提示して公開してよいか確認し、**許可された ID だけ**を日付・プロジェクトの注記付きで `.gitleaks.toml` の許可リストに追加する。検出を避けるための書き換えはしない。
