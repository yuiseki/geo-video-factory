# 動く図の型と現行レンダラーとの接続

## 1. 実装手段の選択（現行レンダラーの境界）

`AGENTS.md` の原則に従い、**実装できない技法をショット JSON に名前だけで書かない。** 表現の複雑さに応じて次の 2 系統から選択する。

| アプローチ | 適用場面 | 具体的な手段 |
|---|---|---|
| **A. 現行レンダラー標準オーバーレイの組合せ** | 地図上の線伸長、3D コロプレス押し出し、数値カウント、折れ線グラフ、簡単なパネルワイプ | `packages/renderer/src/types.ts` の `line` (`draw`)、`polygon` / `choropleth` (`extrude` / `rise`)、`counter`、`chart` (`drawSec`)、`label`、`quote`、`panel` を時間差（`show: [start, end]`）で組む。 |
| **B. 決定論的カスタム図版の連番・動画組込** | プレート断面衝突、熱水循環、分解図（Anatomy Reveal）、多系統タイムラインなど、SVG/Canvas/Three.js/Manim で描く「動く図」 | 時刻 `t` 駆動の HTML/SVG（または Manim / Three.js / Lottie）を Playwright 等で連番 PNG または mp4 に書き出し、`chapter_pipeline.py` で章として結合するか、背景・地図と合成した動画素材として組み込む。 |

> [!NOTE]
> 現行の `PanelOverlay`（`type: "panel"`）は静止画（PNG/JPG/SVG 画像ファイル）を左から右へワイプ表示＋緩やかなズームで出す仕様であり、動きのある HTML ページを直接埋め込む機能は持たない。図版内部を自在にアニメーションさせたい場合は、アプローチ B（章動画・連番として事前レンダリング）または `packages/renderer/` 自体の拡張（TDD で `test/` にテスト追加）を行う。

## 2. 地理・地学・土木の代表的な「動く図」の 4 つの型

### 型 A: 移動・衝突型（プレートテクトニクス・海流・交通流動）

- **伝えること**: 離れた場所から移動体が近づき、境界でぶつかる・合流することで地形や現象が生まれる因果。
- **時間軸の構成例（4 秒）**:
  1. `0.0〜0.5s`: 舞台（本州側・海溝・プレート境界線）を `out` で固定表示。
  2. `0.5〜2.2s`: 移動体（海底火山群・矢印）を `inOut` で北上・接近させる。
  3. `2.2〜3.0s`: 衝突と同時に結果（隆起・陸地化）のハイライトとラベルを `0.15s` Stagger で表示。
  4. `3.0〜4.0s`: 静止して視聴者に結果を読ませる（余韻）。

### 型 B: 循環・上昇型（熱水循環・水循環・火山ガス・物質輸送）

- **伝えること**: 地下や広域の閉じたループ・経路を辿って物質やエネルギーが運ばれ、特定の場所に結果が溜まる仕組み。
- **時間軸の構成例（4〜5 秒）**:
  1. `0.0〜0.6s`: 地層・断面・熱源（マグマ溜まり等）の静的ベースを提示。
  2. `0.6〜1.8s`: 下降流（雨水・海水の浸透）を `stroke-dashoffset` で上から下へ伸ばす。
  3. `1.8〜3.0s`: 加熱・上昇流（熱水の上昇）を色変化とともに下から上へ伸ばす。
  4. `3.0〜3.8s`: 深度ごとの生成物（「浅い層＝金鉱脈」「地表付近＝温泉」等）を順番に点灯・ラベル表示。
  5. `3.8〜5.0s`: 静止保持。

### 型 C: 分解・構造展開型（Anatomy Reveal：地形断面・土木インフラ・都市構造）

- **伝えること**: 普段見えない地下構造や多層構造の「中身と役割の対応」。
- **時間軸の構成例**:
  - アイソメトリック図や断面図のレイヤーを「地表 → 浅層 → 深層」または「基礎 → 構造体 → 表層」の順に `0.15s` ずつずらして `out` で展開し、展開完了した層から順に短い引き出し線（`draw`）とラベルを添える。

### 型 D: 状態遷移・しきい値型（防災・インフラ監視・統計変化）

- **伝えること**: 通常の状態から、ある数値・時間・境界を越えた瞬間に状況が一変する局面転換。
- **時間軸の構成例**:
  - 正常時は動きを最小限にして静止を基準とし、数値カウントや波形がしきい値に達した瞬間に `data-mode` 切替で面・反転ラベル・警告語を一斉更新する（詳細は `geo-video-console-layout` の `state-and-motion.md` を参照）。

## 3. 1 シーン 1 メッセージの原則との統合

- 動く図は情報密度が高くなりやすいため、**1 ショット（1 つの動く図）につき伝える因果は 1 つだけ**にする。
- 2 つの因果がある場合は、1 枚の動く図に無理に詰め込まず、前半ショット（例：第1章A「北上と衝突」）と後半ショット（例：第1章B「熱水循環」）に分割する。
