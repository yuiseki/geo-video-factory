# 参考動画の分析

利用者が良いと感じた動画から、真似できる「型」と、その動画が伸びた (または伸びなかった) 理由の仮説を取り出す。感想を言い換えるのではなく、測った数字とコマで裏づける。

## 流れ

1. 利用者に聞く: 動画の URL、どこが良いと感じたか (一言でよい)、比べたい自分の動画があるか。良いと感じた点は分析の出発点であって結論ではない。
2. 取得する: 本体 (1080p)、メタデータ、概要欄、サムネイル、字幕を、リポジトリの外の保管庫に 1 本 1 フォルダで置く。[references/acquire.md](references/acquire.md)
3. 測る: 画面の切り替わり、音量と無音、話す速さ、コマの一覧、章の頭、カメラと写真の動き、見た目の変化。[references/measure.md](references/measure.md)
4. 見る: コマの一覧と字幕を時刻つきで読み、冒頭、骨組み、区切り、画の文法、終わり方、誠実さ、題とサムネイルを観点ごとに書く。[references/viewpoints.md](references/viewpoints.md)
5. 数字を読む: 再生数を登録者数や公開からの日数で割り、同じチャンネルの別の動画と並べる。[references/metrics.md](references/metrics.md)
6. 報告する: 分析と、自分たちの動画への持ち帰りの候補を、テンプレートでできるか (○ △ ×) を添えて出す。どれを取り入れるかは利用者が決める。[references/report.md](references/report.md)

複数本を分析したら、本数をまたいで共通すること、同じチャンネルの中で差が出たことを別にまとめる。これまでの分析で繰り返し見えた傾向は [references/findings.md](references/findings.md)。新しい分析でこの傾向が崩れたら、そこを書き直す。

## 守ること

- 取得した動画、字幕、サムネイルは個人の参考用で、再配布しない。リポジトリや公開する成果物に入れない。
- スキルや公開する文書には、個々の動画やチャンネルの名前を書かない。知見は「立体地図の思考実験」「写真が主役の紀行解説」のような型の言葉で書く。名前は手元の保管庫の分析ファイルにだけ残す。
- 他人の動画の構成、言い回し、画を、そのまま写さない。持ち帰るのは型 (なぜ効くのか) で、中身は自分の題材で作る。
- 自動字幕は音声認識なので誤字が多い。文字数は目安として扱い、引用するときは動画で確かめる。
- 再生数や高評価の数は取得した時点の値。公開からの日数を必ず添える。
- 数字の差に理由を付けるときは「〜と読める」「〜に対応しているように見える」と仮説として書く。1 本の比べで因果を言い切らない。
- 測定は時間とメモリを使う。ホストの資源制限ルールに従って上限を掛けて流す。

自分たちの動画も同じ物差しで測って並べると、何が足りないかが数字で見える。
