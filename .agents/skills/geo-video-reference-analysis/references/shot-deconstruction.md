# ショット単位の逆算分解と再現プラン

動画全体の印象や集計値だけでは、「どの瞬間に何が切り替わり、なぜ見続けられるのか」「自分たちの制作基盤 (`MapLibre` + `Three.js` + `Playwright` + `FFmpeg` + `VOICEVOX`) でどこまで再現できるのか」が見えにくい。
特定の導入（冒頭 30 秒）、転換点、あるいは 1 本全体の作りを深く学びたいときは、動画を **ショット単位** に切り分け、**4 層構造の分解ドキュメント (`SHOT_PLAN.md`)** へ落とす。

- 出力先も保管庫のフォルダ (`<保管庫>/<ID>/SHOT_PLAN.md`) とし、リポジトリには入れない。
- リポジトリや各スキルへ戻すのは、動画固有の題材を外して抽象化した「型」だけにする。

## 1. 4 層構造で整理する理由

長尺動画のすべてのショット詳細を一度に読むと文脈が膨らむ。そこで、粗い全体像から細かい設計へ段階的に読める 4 層に分ける。

| 層 | 内容 | 使う場面 |
|---|---|---|
| **Layer 1: 全体要約・フック構造** | 長さ、ショット数、カット頻度、ショット長分布、カメラ動きの割合、冒頭 5 秒 / 30 秒のフック構造、全体を貫く物差し | 動画全体のテンポと骨組みを素早く掴む |
| **Layer 2: マスターショットタイムライン** | 1 ショット 1 行の表（開始-終了、秒、章、測定したカメラ動き、カット種別、画面レイヤー、音声レイヤー、再現手段、発話抜粋） | 展開の緩急、場面の型の偏り、後半のだれを一覧で見る |
| **Layer 3: 主要ショット詳細分解と再現プラン** | 導入・章頭・見せ場など代表ショットの 3 層分解と、観察事実 / 推定の分離、`geo-video-factory` での再現設計 | 自分たちのショット JSON やパイプライン設計へ落とす |
| **Layer 4: 音声・リズム・字幕アライメント** | 話者交代・発話速度・沈黙の間、BGM の連続性とテンポ (BPM)、効果音・音ハメ、字幕の位置・色・縁取り | VOICEVOX 台本、BGM ダッキング、効果音タイミングの設計 |

## 2. 観察の 3 層分離と「事実 / 推定」の区別

1 つのショットを読むときは、画面と音を混ぜず **3 つの層** に分けて記録する。

1. **ベース画層 (Base picture)**: 地図カメラ (2D / 3D 地形 / 3D 建物)、画面いっぱい写真、平らな図解・モーションダイアグラム、タイトルカード、左右比較、画面収録・実写。
2. **オーバーレイ / パッケージング層 (Overlay)**: 字幕（位置・文字サイズ・縁取り・話者色分け）、地名・注釈ラベル、常駐物差し（時計・年・目次）、数値強調カード、立ち絵・PiP、出典表記。
3. **音声層 (Audio)**: 声（話者数・合成/肉声・間）、BGM（連続/途切れ・ダッキング・テンポ）、効果音（カット点や図解出現との一致＝音ハメ）。

Layer 3 の詳細メモでは、必ず **観察事実**（フレームと波形・字幕から直接確認できたこと）と **推定**（制作手法や狙いの仮説）を分けて書く。確認していない制作ツールや素材元を事実として断定しない。

## 3. 分類語彙（マスタータイムライン記入用）

### カット種別
- `ハードカット`: 瞬時に別画へ切り替わる（`cuts.txt` で検出される標準の境界）
- `ディゾルブ / フェード`: 溶けるように切り替わる（`cuts.txt` に出にくいのでコマ一覧で補う）
- `章カード転換`: 本編を暗転または専用画面へ切り替えて章番号・目次を見せる
- `連続カメラ`: カットを挟まず、1 つの地図や 3D 空間の中をカメラ移動で場面転換する

### カメラ動き
`motion.py` の出力 (`zoom_in` / `zoom_out` / `pan_left` / `pan_right` / `pan_up` / `pan_down` / `static`) を基準にし、地図特有の `オービット`、`ピッチ変化 (俯瞰↔低空)`、`トラッキング` を必要に応じて補足する。

### 再現手段の 4 分類 (`geo-video-factory` 基準)

参考動画の各ショット・演出要素を、自分たちの制作基盤でどう再現するかで 4 分類する。

| 再現手段 | 意味 | `geo-video-factory` での具体例 |
|---|---|---|
| **`renderer標準`** | `packages/renderer/` の既存ショット JSON でそのまま再現できる | 地理院タイル + 3D地形/建物カメラ、写真オーバーレイと緩やかなパン/ズーム、ラベル・数値カード、タイトルカード、字幕、立ち絵、VOICEVOX 掛け合い |
| **`pipeline事前生成`** | `packages/pipeline/` や Python / FFmpeg スクリプトで事前データや素材を生成して組み込める | 衛星色度テクスチャ生成、統計コロプレス GeoJSON、EXIF 写真マーカー抽出、BGM 自動ダッキング (`sidechaincompress`) と `-14 LUFS` マスタリング、章の並列書き出しと結合 |
| **`素材収集`** | 外部または自前の素材収集とライセンス確認・出典記録が必要 (`geo-video-materials`) | Wikimedia Commons・個人写真、古地図、ピクトグラム・イラスト、立ち絵、BGM・効果音 |
| **`要新規実装`** | 現行レンダラー/パイプラインにない表現。共通パッケージへの機能追加候補として切り出す | 未対応の比較スライダー/ワイプ UI、専用モーションダイアグラム表現、新しい画面遷移効果、複雑な計器アニメーション |

## 4. 再現可能性の評価軸

`持ち帰りの候補` を絞り込むときは、単なる「かっこいい」ではなく次の 3 軸で評価する。

1. **技術的再現度**: 上の 4 分類（`renderer標準` 〜 `要新規実装`）と、既存の対応表 (`geo-video-visuals/references/README.md` の `○ / △ / ×`) の整合。
2. **権利・誠実さのリスク**: 実写ロケ、他社 3D タイル、AI 生成イメージに依存していないか。代替する場合（地理院オルソ + PLATEAU、模式図など）、画面・声・概要欄の 3 か所で誠実に断り書きを入れられるか。
3. **再利用性（コスト対効果）**: その作品 1 回限りの凝った演出か、複数の章や今後の作品でも使い回せる「型」か。`要新規実装` は、繰り返し使える型に絞って共通パッケージへ提案する。

## 5. 再現プラン生成の手順

1. まず [measure.md](measure.md) の手順で `cuts.txt`、`motion.tsv`、`transcript.txt`、`sheets/`、`chapters/all.jpg` を出力する。
2. `shot_plan.py` で測定値を結合し、4 層構造の雛形を生成する。

```bash
S=<skill-dir>/scripts; D=<保管庫>/<ID>
python3 $S/shot_plan.py \
  --cuts $D/cuts.txt \
  --motion $D/motion.tsv \
  --transcript $D/transcript.txt \
  --info $D/<ID>.info.json \
  --out $D/SHOT_PLAN.md
```

- 構造化データとして別の処理に渡したい場合は `--json` を付ける。
- 短すぎるノイズカット（フラッシュや字幕切替の誤検出）が多い場合は `--min-shot 1.0` のように閾値を上げる。

3. `sheets/` と `chapters/all.jpg` を見ながら、Layer 2 の空欄（`カット種別` / `画面レイヤー` / `音声レイヤー` / `再現手段`）を埋める。長尺動画で全ショットを埋める必要がないときは、**冒頭 30〜60 秒・各章の頭・最も動きが変わる場面** を優先する。
4. Layer 3 に代表ショットの「観察事実 / 推定 / 再現設計」を書き、Layer 4 に音声・テンポ・字幕同期の気づきをまとめる。
5. `要新規実装` や高効果な型を抽出し、[report.md](report.md) の「持ち帰りの候補」表へ転記して利用者に提案する。
