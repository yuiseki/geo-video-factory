# PLATEAU++ ultra: before

世界モデル (`packages/pipeline/world_model/`) の今の出力を、渋谷以外も含めた 8 か所で記録するプロジェクトです。
改善の試行錯誤は `projects/2026/11/26/plateau-pp-ultra-after/` で行い、ここの出力と並べて比べます。
ここでは何も改善しません。

## 作り方

```sh
OVERPASS_URL=<自前の Overpass> python projects/2026/11/26/plateau-pp-ultra-before/before.py [名前 ...]
python projects/2026/11/26/plateau-pp-ultra-before/sheet.py
```

リポジトリのルートから、`packages/pipeline` の Python で流します (ホストの資源制限に従う)。`blender` が要ります。

1. PLATEAU++ v0.1.0 を、版付きの共有キャッシュから使う (`plateau_pp.cached`)。
2. 地面の高さは、PLATEAU++ の面があれば中心から 150 m 以内の面の下から 2%、無ければ `areas.json` の `ground_z`、それも無ければ地理院の DEM (10 m 格子) に楕円体高との差 36.7 m を足したもの。DEM は斜面で 3〜5 m ずれる (渋谷、上野)。
3. `world_model/pp_scene.py` で昼と夜の場面を作る。渋谷は CC0 のアトラス 5 つと地面を、ほかの 6 か所は `atlas_before.py` で作ったアトラスを重ねる。
4. `render_views.py` で 3 つの視点から描く。上空から斜め (300 m 離れて 250 m 上)、屋上の高さ (90 m 離れて 45 m 上)、歩く人の目の高さ (1.6 m) です。目の高さの地点は、中心から 80 m 以内で、指定の方向にいちばん遠くまで見通せる所を当たり判定で選ぶ。
5. `sheet.py` が `out/sheet_day.jpg` と `out/sheet_night.jpg` にまとめる。

`out/` は使い捨てで、流すたびに作り直します。

## アトラス作り (`atlas_before.py`)

渋谷以外の 6 か所にも、今の道具のままアトラスを作った。工程は写真の取り込み (共有の置き場から)、PLATEAU++ の面、SfM (pycolmap)、基準写真 (`geo/photo_place.py`)、街の座標への合わせ込み、昼夜の振り分け、アトラス。SfM と基準写真は、z と Mac で分担できる (画像の名前が写真の参照から決まるので、別の機械の結果をそのまま持ち込める)。

分かったこと:

- SfM はほとんどつながらない。場所ごとの CC0 写真の集まり (27〜254 枚) は、撮影者も地点もばらばらで、新宿は 0 枚、銀座、秋葉原、浅草は 3 枚、上野は 6 枚、丸の内は数枚のモデルしかできなかった。
- そのため、どの場所も、撮影地点の座標を持つ写真を 1 枚ずつ空と建物の境界線で置く経路になった (中心から 300 m 以内の 5〜8 枚)。
- その 1 枚ずつの置き方が、空の写らない写真 (店の中、夜の路地、像、人の背中) を、コスト 0 のまま意味のない位置に置く。銀座、秋葉原、新宿の 21 枚のうち 15 枚がそうだった。
- 結果として、写真で埋まった壁は 0〜0.8% しかない。

`atlas_before.py` には after が使う引数もある。`--min-cost` と `--alone` は、置き場所の決まらない写真 (`geo/photo_place.alone`) を外す。写真が 1 枚も残らなければ空の昼夜のレイヤーを書き、after はその場所の写真のアトラスを使わない。before の出力はこれらを使わずに作った。

そのほか、作っている途中で直した不具合:

- `pp_scene.py` が、RTC が `[0, 0, 0]` のタイル (台東区) を範囲外として捨てていた (浅草 37 タイル中 3、上野 38 中 1)。タイルの範囲で選ぶようにした。
- `plateau_mesh.py` が補完の建物のタイルを横倒しに読んでいた。
- pycolmap の SIFT が全コアで走り、32 コアの機械で 12 GB を超えた (`--threads=6`)。
- Blender の EEVEE は、背景で続けて描くと、カメラを動かしても前の視点の絵を出すことがあった (銀座)。同じ Blender の中で場面を進めても描き直しても直りきらないので、`before.py` は視点ごとに Blender を起動する。`render_views.py` は、1 つの Blender で複数の視点を描くときは、前の視点とほぼ同じ画素なら描き直し、2 回続けば失敗にする。
- アトラスの建物群は、1 棟ずつの設定では 3 万面で 20 GB を超えたので、渋谷の「周辺」と同じ設定で中心から 120 m に絞った。

## 見るところ (レビューの 5 つの伸び代)

1. `pp_scene.py` が PLATEAU++ v0.1.0 の焼き込みを生かしていない。壁の頂点色 (`COLOR_0`) と夜の窓 (`emissiveTexture`) を捨て、最初に見つかった画像だけを発光させる。昼なのに黒い壁に窓が光る建物や、テクスチャの無い面の灰色 (0.5, 0.5, 0.52) として出る。
2. 写真のアトラスが、見た写真の枚数 (`seen.png`) を 0.05 で二値に切って重なる。浅い角度で 1 枚だけかすめた壁が、引き伸ばされた縞模様になる (渋谷)。
3. 写真に写らなかった面は、`--fill=mean` で平均の 1 色に塗られる。
4. 位置合わせ (`photo_place.py`) が空と建物の境界線しか見ない。空の見えない写真 (路地、夜、店の中) は、落ちるのではなく、コスト 0 のまま意味のない位置に置かれ、アトラスに間違った色を塗る (上の「分かったこと」)。
5. 地面は地理院の写真か一様な灰色の板で、横断歩道、路面の質感、街灯などが無い。
