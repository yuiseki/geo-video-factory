## 問い
東京23区（および玉川上水など関連する主要上水路）において、商用利用可能なオープンデータのみから「元々川だった場所（暗渠・DEM谷筋・埋立掘割・旧上水・旧河道）」をどれだけ特定・統合でき、それらは過去の浸水実績とどの程度空間的に重なるか。

## 方法

1. **座標系と面積・距離の計測**: すべての距離・面積計測、バッファ生成、Douglas-Peucker 簡略化（許容誤差 `2.5〜3.0 m`）は平面直角座標系第IX系（`EPSG:6677`）で行い、最終納品 GeoJSON は `EPSG:4326`（`[lon, lat]` 順）に変換して出力した。`MultiLineString` および `MultiPolygon` は単一ジオメトリへ分解した。
2. **DEM 水文解析 (`terrain-hydrology/scripts/hydro.py`)**: `dem5a_z15`（5m LiDAR DTM）を主とし、水面マスク（`e`）および欠損セル `434,135` セルを `dem_z14` で補完した上で、`EPSG:6677` の `10 m` 格子（`4,586 × 4,264 = 19,554,704` セル、有効 `17,090,760` セル、面積尺度誤差最大 `0.0002`）へ双線形変換した。Priority Flood による窪地埋めと D8 最急降下により流向・集水面積を算出し、河道抽出閾値は `--stream-km2 0.5` とした（比較用に `1.0 km²` では `779` 本・`1,848.4 km` となることを広域で確認）。河口・合流点の流出点8点のうち、目黒川河口（`54.00 km²`）・石神井川王子（`46.47 km²`）・妙正寺川落合（`21.60 km²`）は `edge_cells = 0`、渋谷川・古川河口（`23.70 km²`）は海岸端接点により `edge_cells = 6` となった。神田川河口や呑川・立会川河口は下流低平地・盛土による分断等で `300 m` 以内に `5.0 km²` 以上の流路セルがスナップされなかった。
3. **レイヤー構築と重複除外・上流→下流揃え**:
   - `01_current_rivers.geojson`: OSM の開渠 `waterway` を23区でクリップ。`LineString` は DEM 標高差（終点が始点より `1.5 m` 以上高い場合）または `pyflwdir` 集水面積順（`valley_dem`）により上流→下流へ揃えた。
   - `02_culvert_and_valleys.geojson`: OSM 暗渠（`tunnel=culvert/yes`, `covered=yes`, 延長 `30 m` 以上、ただし無名断片は `100 m` 以上で `confidence: "high"`）と緑道・親水路（`confidence: "medium"`）に、DEM 抽出谷筋（`0.5 km²` 閾値、現行開渠 `50 m`・大河川 `150 m`・OSM暗渠 `30 m`・`03` 掘割 `20 m` バッファを除外し、延長 `100 m` 以上かつ最大標高 `4.0 m` 以上の台地谷地形に限定、`confidence: "estimated"`）を統合した。さらに、国土地理院 地形分類（人工地形）`code 11005`（臨海埋立地）と重なる範囲をすべて除外した。
   - `03_filled_canals.geojson`: 建物・運動場・廃線跡・埋立地公園・現存防潮堤を除外した上で、OSM の外濠公園・大横川親水公園・竪川河川敷公園・横十間川親水公園・仙台堀川公園・曳舟川親水公園・浜町川・三味線堀等と、国土地理院空中写真 (`ort_USA10`, `ort_riku10`) で位置・幅員を確認した新橋・銀座・日本橋・下町の主要掘割（三十間堀・京橋川・桜川・汐留川・築地川本流/東/南支川・楓川・東/西堀留川・龍閑川・箱崎川・外濠川・山谷堀）を当時の川幅（`15〜30 m`）の `Polygon` として統合した。
   - `04_old_aqueducts.geojson`: 23区外上流部を含む `osm-japan-src-2026-08` から玉川上水・千川上水・神田上水石樋・六郷用水を抽出。
   - `05_former_channels.geojson`: 国土地理院 `experimental_landformclassification1` の旧河道3コードをタイル境界結合後に23区でクリップ（`100 m²` 以上）。
4. **浸水実績との空間結合**: `06_flood_overlap.geojson` として、23区内浸水実績ポリゴン `4,759` 件から `02`/`03`/`05` までの最短距離（`EPSG:6677`）を計測し、`50 m`・`100 m` 以内の重なりを集計した。

## 失敗の型

| ID | 判定 | 根拠 |
|---|---|---|
| F1 | 確かめた | 結合・クリップ前後のフィーチャ数・延長・面積を [05_build_layers.py](scripts/05_build_layers.py) で逐次出力し、全 GeoJSON の必須キー欠損 0 件を確認した |
| F2 | 確かめていない | 浸水実績との重なり率（`36.9%` / `45.3%`）について、ランダム点配置や市街地面積比に対する統計的ベースライン比較は実施していない |
| F3 | 当てはまらない | 教師あり予測モデルの学習・評価を行っていない |
| F4 | 当てはまらない | 観測努力を特徴量とする予測モデルを構築していない |
| F5 | 当てはまらない | 先行研究や既存通説と相反する想定外の発見を主張していない |
| F6 | 確かめた | 報告書のパラメータ（`--stream-km2 0.5`、`EPSG:6677`、`50 m` / `100 m` 等）は実行スクリプトとログに一致している |
| F7 | 確かめていない | DEM 河道閾値（`0.5 km²` vs `1.0 km²`）の変更に伴う水系別延長や浸水重なり率の感度分析は未実施 |
| F8 | 確かめた | 本文・表の数値はすべて [layer_summary.csv](outputs/layer_summary.csv)、[basin_comparison.csv](outputs/basin_comparison.csv)、[summary.json](outputs/summary.json) から転記した |
| F9 | 確かめた | 各データセットの版・スナップショット日・商用可否を [credits.json](outputs/credits.json) に記録し、23区境界は `jp-admin-2026-09` で統一した |

## 確かめていないこと

- **F2（統計的ランダム基準との比較）**: 浸水実績ポリゴンと暗渠・旧河道との重なり率について、無作為な空間配置や流域密度で調整した期待値との有意差検定は行っていない。また、`tokyo-flood-record-jp` には同一イベントの分割ポリゴン重複が含まれるため、ポリゴン行数ベースの割合として解釈する必要がある。
- **F7（閾値変更に対する感度分析）**: DEM 谷筋抽出の集水面積閾値（`0.5 km²`）を変えた場合の 23 区内総延長および浸水重なり率の変化は比較していない。
- **未収録水路・盛土分断の限界**: `hydro.py` には stream burning や breach が無いため、下流低平地や盛土（道路・鉄道盛土）で分断された河道は DEM 解析のみでは連続しない箇所がある。また、三田用水・品川用水や細街路の無名暗渠、暗渠化された都心掘割（三十間堀・東/西堀留川・龍閑川等の道路下区間）のうち OSM に緑道・水路として未収録の区間は、本成果物には含まれていない（迅速測図・戦前空中写真による手動トレース補完は今後の拡張対象）。
