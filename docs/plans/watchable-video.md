# 指示書: サブエージェントでも破綻のない映像を再現できるリポジトリにする

この文書は、この作業を引き継ぐエージェントと持ち主のための指示書です。進捗はここに書きません (作業の記録は各自の記録の仕組みへ)。ゴールや段階を変えたときだけ、この文書を直します。

## ゴール

白紙のサブエージェントが、題材 1 行とこのリポジトリだけを渡されて、音声付き 60 秒の動画を作れること。合格の条件は 3 つです。

1. 破綻なし: 検品コマンド 1 本が exit 0 を返す。
2. 再現性: 同じ入力から 2 回書き出して、全フレームが一致する (許容差は数値で決めて、ここに書く)。
3. 違和感なし: 持ち主が通常速度で 1 回見て、直したい箇所が 0 件。

題材の型 3 種 (地形、都市の建物、統計の可視化) で、それぞれ別のサブエージェントが 1 回で通したら完了です。

## 約束しないこと

- 「気持ちの良さ」は機械で保証しません。検品が保証するのは破綻が無いことまでで、最後は持ち主の目視です。
- 既存のプロジェクトを全部は完成させません。手本にしないものは凍結し、理由を README に残します。
- Blender で描く系統 (`packages/blender/`、`projects/2026/11/20/liminal-space-city-walk-with-bgm/`) は制作の流れが違うので、この 3 種とは別枠です。

## 段階

前の段階の完了条件を満たしてから次へ進みます。順番の理由は、検品が先にあれば、手本づくりとスキルの評価を持ち主の目視なしで回せるからです。

### 1. 破綻の型の台帳

- すること: 既存プロジェクトの版の履歴 (ショット JSON の差分、判断のメモ) と持ち主の指摘から、破綻と違和感を型に分ける。例: カメラの急加速、ラベルの重なり、タイルの欠け、字幕と声のずれ、暗転、章の境界の音量差。
- 置き場: `.agents/skills/geo-video-production/references/` に一覧として置く。
- 完了条件: 型ごとに「機械で測れる」「人しか見られない」の区別と、測り方の案が付いている。持ち主が一覧を読んで、抜けが無いと言う。
- 持ち主の作業: 過去に気になった箇所を挙げる。どのプロジェクトから始めるかを決める (未決。候補は下)。

### 2. 検品ゲート

- すること: 台帳の「測れる」型を、1 本のコマンドにまとめる。いまは `packages/pipeline/video/` の `video_qa.py`、`video_inspect.py`、`frame_check.py` に分かれている。
- 決まり: 失敗は必ず exit 1。測れなかった項目を合格にしない。検査を足すたびに、その型でわざと壊した入力のテストを先に書く。
- 完了条件: 型ごとに用意した壊れた動画を全部落とし、良い動画を通す。テストは `packages/pipeline/tests/` にあり、実データなしで走る。

### 3. 再現の型

- すること: プロジェクトごとに、入力の固定 (データの版、乱数の種、声) と、書き出しのコマンド 1 本を定める。固定したものは文字のファイルに残す。
- 完了条件: 手本 1 本を 2 回書き出して、フレームが一致する。一致しない原因 (時刻、取得のたびに変わるタイル、並列の順序) を突き止めて、型のほうを直してある。

### 4. 手本の完成

- すること: 既存プロジェクトを「完成させる」「凍結して理由を書く」に分ける。題材の型ごとに 1 本を最後まで仕上げる。
- 完了条件: 手本 3 本がゴールの条件 1〜3 を満たす。作る途中で見つかった型の不具合は、その作品の中で直さず、スキルと `packages/` へ戻してある。
- 持ち主の作業: 分け方の承認と、各手本の最終の目視。

### 5. スキルの評価

- すること: 白紙のサブエージェントに題材を渡して作らせ、ゲートで採点する。失敗はスキルの文面か `packages/` へ戻す。
- 決まり: 直すのに使った題材で効果を測らない。評価用の題材を別に取っておく。サブエージェントの報告の数字は、自分で読み直してから使う。
- 完了条件: 3 種の題材が 1 回で通り、取っておいた別の題材でも通る。

### 6. 定着

- すること: ゲートと再現の検査を、CI (`.github/workflows/`) と `geo-video-production` の手順に入れる。
- 完了条件: 新しいプロジェクトは、ゲートを通らないと完成と書けない。`AGENTS.md` の「進め方の原則」がこの流れに合っている。

## 未決のこと (持ち主が決める)

- 台帳をどのプロジェクトから作るか。版を多く重ねたものほど型を多く拾える。候補: `projects/2026/11/13/dotonbori/`、`projects/2026/11/19/izu-hot-spring-and-gold/`、`projects/2026/11/19/tokyo-river-recall/`。
- 再現性の許容差 (完全一致か、差の上限か)。段階 3 で実測してから決める。
- 手本にするプロジェクトと、凍結するプロジェクト。

## 作業の決まり

`AGENTS.md` に従います。この作業で特に効くものだけ挙げます。

- テストを先に書く。`packages/pipeline` は `python -W error -m unittest discover -s packages/pipeline/tests` が通り、カバレッジの下限 (`packages/pipeline/.coveragerc`) を割らないこと。全体は `packages/test.sh`。
- モジュールは 400 行まで (`packages/pipeline/tests/test_architecture.py`)。`packages/pipeline` のモジュールはサブパッケージから import する (`from video import video_qa`)。
- 実データを読む書き出しは、ホストの資源制限の規則に従って流す。
- 書き出しは新しい版の名前へ。既存の成果物を上書きも削除もしない。
- 機械固有のパス、資格情報、再配布できない素材、確かめていない写真の ID を入れない。push の前に gitleaks を通す。
- 複数のエージェントが同じ作業ツリーを使う。`git add -A` と stash を使わず、自分のファイルだけを add する。push の前に fetch する。

## 分かっていて直していないこと

- `geo/seasonal_ortho.py` は SCL (分類値) を線形補間で読むので、境界に実在しない分類値ができる。最近傍で読む引数が要る。
- `photos/photo_catalog_sources.py` は取得の失敗を握りつぶす箇所がある。
- `buildings/plateau_3d.py` のテクスチャ縮小は、縮めた画像を足すだけで元の画像を GLB に残す。
- `video/scene_assembly.py`: `--night-from` が曲全体の雑音と残響を変える。夜の境界は 8 秒単位に丸まる。フレームの大きさは 1 枚目しか確かめない。
- Commons の写真カタログを過去に作っていれば、CC BY を CC0 と記録した行が残っているかもしれない (取得のコードは修正済み)。ライセンス名が CC0 で URL が `licenses/by/` の行を探す。
